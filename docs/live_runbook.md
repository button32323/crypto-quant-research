# 实盘操作手册（Live Runbook）

> **状态：未激活。** 前置条件：30 天 paper 验证 PASS + 用户逐笔授权 + 账户/本金确认。
> 原则：手动执行、逐笔确认；脚本只生成计划与对账，不具备下单能力。

## 1. Day 0：账户准备

1. 登录 Hyperliquid，确认入金到账（USDC）；
2. **手动执行模式（推荐首次）**：网页操作即可，不需要 API key；
3. **半自动模式（可选，进阶）**：
   - 创建独立 API wallet / agent key，权限仅交易；
   - **禁止提现权限**；开启 IP 白名单；定期轮换；
   - 不要把主钱包私钥写入任何脚本；
4. 记录：账户地址、入金金额与时间、实际汇率。

---

## 2. 首次建仓（人工执行，约 5 分钟）

```powershell
cd <repo>\10_收入\11_paper_trading
$py = "<python>"
& $py live_order_plan.py --capital <真实资本>
```

1. 打开 `LIVE_PLAN.md`，确认状态为 `READY_FOR_AUTHORIZATION`；
2. 核对订单：资产、方向（现货 BUY / 永续 SELL）、数量、参考价、保证金；
3. **先买现货腿**（PURR/USDC、HYPE/USDC），确认成交；
4. **立即开永续空头**（同名义、1x），确认成交；
5. 从交易所导出/手工填写持仓快照 `snapshot.json`，运行对账：

```powershell
& $py reconcile.py --actual snapshot.json --expected state.json
```

6. 对账必须 **PASS**（净 delta ≤5%、单侧杠杆 ≤1x、数量偏差 ≤1%）；否则补齐裸腿或减仓；
7. 记录建仓价、数量、手续费到对账表。

## 4. 每周 / 每月

| 频率 | 动作 |
|---|---|
| 每周 | `reconcile.py` 对账；汇总资金费收入；检查 delta 漂移（>10% 资本则调回） |
| 每月 | 对比 `INCOME_EXPECTATION.md` 的预期区间；统计手续费/滑点；评估资金费环境变化 |
| 每季度 | 复盘：收益来源、偏差原因、是否继续（不是调参） |

---

## 5. 事件处理（按优先级）

| 事件 | 动作 |
|---|---|
| **资金费连续 12 次（约半天）为负** | `exit_plan.py` 生成平仓计划 → 人工确认 → 平仓；停止新仓，记录 |
| **组合回撤 ≥5%** | 全部平仓，停止交易，复盘 |
| **单日亏损 ≥2%** | 当日停止；次日评估是否恢复 |
| **保证金率 < 2x** | 立即减仓或补保证金 |
| **交易所/API 故障** | 手动登录平仓（`exit_plan.py --reason emergency`），不要等 |
| **极端行情（闪崩/插针）** | 两腿同时市价平仓，接受滑点；不抄底 |
| **连续 2 周低于历史 p5（年化 14.3% 折算）** | 暂停，复盘；不调参 |

**平仓顺序**：先平永续（BUY reduce-only）→ 立即平现货；若只成交一腿，立刻市价补齐另一腿，不留裸腿过夜。

## 6. 权限与安全

- API key：只交易、禁提现、IP 白名单、独立 agent key、定期轮换；
- 不把私钥/助记词写入脚本或聊天；不截图私钥；
- 所有订单人工确认；脚本只做计划/对账/记录；
- 不在公共网络/未受控设备上操作账户。

## 8. 红线（写死，不因行情/情绪改变）

1. 不承诺收益；不代客操作；不碰客户资金；
2. 不借钱、不加杠杆 >1x；
3. 不做未验证的方向性交易；
4. 不因亏损加仓摊平；
5. 不跳过 `reconcile.py` 对账；
6. 实盘操作必须逐笔经用户确认。
